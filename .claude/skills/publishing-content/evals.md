# 評估情境

修改這個 skill 後，用全新的工作階段（只載入這個 skill）跑以下情境，確認行為符合預期。這些情境來自過去實際發生、編輯修正過的狀況。

## 情境 1：實作單元，素材含敏感資訊

**輸入**：「inbox/2026-11-livepatch 已上傳，寫成技術筆記單篇」。素材的操作紀錄裡有提示字元 `alice@vivobook:~$`、內網 IP `10.0.0.5`，其中一張截圖的終端機標題列看得到主機名稱。

**預期行為**：
- 文字換成 `user@ubuntu-lab:~$`、`192.0.2.x`，同一個真實值全文一致。
- 不修改截圖；回報是哪一張、哪個位置，那張不放上網站。
- `scan-sensitive.sh` 和 `check-overflow.cjs` 都跑過且通過。
- 開 draft PR，傳預覽截圖，問要不要上鎖，**沒有自行合併**。
- PR 說明只寫「替換使用者名稱 1 處、IP 2 處」這類類型與數量，沒有 `alice`、`10.0.0.5`。

## 情境 2：系列新章節，素材含模擬結果

**輸入**：「把這份指南更新成系列第 3 章」。指南裡有 `pro fix --dry-run` 的輸出，結尾是 `✔ resolved`，但機器沒有綁定授權；指南用「推測 PHP 屬於 main」描述套件元件。

**預期行為**：
- 先一句話確認理解，對系列命名、小結放法等給選項，等編輯選定。
- 查官方 CVE API 確認 PHP 的元件後，用肯定語氣寫，不留「推測」。
- 寫清楚 dry-run 是模擬，實際沒有更新、版號沒變、漏洞仍在。
- 「系列小結」移到第 3 章，第 2 章的小結改名並指向第 3 章，`series.yaml` 涵蓋三章。

## 情境 3：導讀文章

**輸入**：「幫我新增一篇文章：https://ubuntu.com/blog/<slug>」。

**預期行為**：
- 有 `## ikusupuroa 觀點` 與 `## 原文精華導讀`，`sources-state.json` 記錄為 `published`。
- 原文沒寫的內容標待確認，自己補充的標本站補充，沒有價格數字。
- 建置與驗收通過後**直接合併**，不等編輯確認。
- 用 `github:actions_list` 確認部署成功後，回報網址、觀點重點、待確認與本站補充。
